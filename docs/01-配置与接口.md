# 配置与接口参考

## 1. 配置 `config/leaderteam.config.json` 与本地覆盖 `config/leaderteam.local.json`

修改后重启 DSH 生效。加载 `config/leaderteam.config.json` 时若同目录存在 `config/leaderteam.local.json`（被 `.gitignore` 忽略），会自动深度合并对象字段（数组以覆盖文件为准），再执行严格字段白名单校验。存在未知字段名、拼写错误或非法免审工具配置时，DSH 拒绝启动并列出全部问题。

| 键 | 含义 |
|---|---|
| `magpie.provider` | DSH 里 Magpie 提供方的 id（Desktop 以 settings 中实际 id 为准） |
| `models.<route>` | 可用模型目录。route = `<provider>/<model>`（含同前缀上游区分后缀如 `@direct`/`@upstream`）。`family` 支持 `gpt`/`glm`/`gemini`/`deepseek`/`claude`/`qwen`/`other`；`efforts` 取 `none/off/minimal/low/medium/high/xhigh/max` 的子集（`none` 在发请求时不传 `reasoningEffort`，适配不支持思考档位的普通模型）；可选 `provider`/`upstreamModel`/`quotaWindows` |
| `roles.leader` | 领队模型与档位。headless 读取此配置；Desktop 新会话没有持久选择时采用此默认，恢复会话保留原选择 |
| `team.leaderModelPolicy` | `enforce`（默认）：实际 provider/model/effort 不符合配置或未知时，团队工具拒绝。`warn` 只提示；`off` 不核对 |
| `roles.gate` | 安全门：`route`/`effort`/`maxTokens`/`timeoutMs`/`retries`/`fallback`。`maxTokens` 是含推理的输出上限（随附配置：门 `8000`、回退 `2000`、讨论 `8000`、裁断 `16000`、串行复核 `2400`，允许任意 `>= 64` 的整数，不再设固定 `16384` 上限）；上限过低会被截断并按失败处理 |
| `roles.discussA` / `discussB` | 两个独立评审请求，各自配置路线和档位，可以使用相同模型，不绑定模型系列 |
| `roles.arbiter` | 独立裁断者，可配置路线和支持的档位 |
| `roles.serialReviewer` | 串行快速复核角色（可选；未配置时自动继承 `roles.discussA` 路线并将 `timeoutMs` 上限收敛至 `180000`、`retries` 设为 `0`） |
| `roles.directExec` | 领队直属执行模型（`team_direct_exec`，可选；未配置时默认取 `team.executionPool[0]`），支持配置 `route`/`effort`/`maxTokens`/`timeoutMs`/`retries`/`fallback` |
| `governance.*` | V2.1/V2.2 治理模式配置（严格字段白名单）：`mode`（仅接受 `"autonomous"` 或 `"approval"`；默认 `"autonomous"` 领队自主派发 + 异步监督 + 四阶段裁断，`"approval"` 为同步审批兼容模式）、`caucusQuorumNumerator`（默认 `2`）、`caucusQuorumDenominator`（默认 `3`，共同构成 2/3 多数门槛）、`maxInternalArbitrationRounds`（默认 `2`，即同案前 2 次走内部预议/会商、第 3 次直接上调人工）、`maxConferenceDialogueTurns`（默认 `2`）、`autoSuperviseStages`（默认 `true`）、`autoSuperviseDispatches`（默认 `true`）、`directExecMaxSteps`（默认 `24`）、`pauseBarrierTimeoutMs`（默认 `30000`） |
| `powerMonitor.*` | V2.2 电池感知式安全收尾配置（严格字段白名单，可随时关闭）：`enabled`（默认 `true`，设为 `false` 完全停用电量检测）、`pollIntervalMs`（后台静默无窗轮询周期，默认 `720000` 即 12 分钟，允许范围 `600000..900000` 即 10~15 分钟）、`lowBatteryPct`（仅电池供电时的收尾触发阈值，默认 `20`）、`resetBatteryPct`（插电或回升重置阈值，默认 `25`；重置仅恢复检测锁存器，绝不自动恢复已暂停工程）。仅读取是否电池供电与电量百分比两项数值，VPS 无电池自动静默跳过 |
| `requestWindow.*` | V2.2 滚动请求次数窗口保护（严格字段白名单，绝不静默跳过双审）：`enabled`（默认 `true`）、`windowMs`（默认 `18000000` 即 5 小时）、`softThrottlePct`（默认 `20`，优先抑制非必要模型列表探测）、`hardPausePct`（默认 `5`，触发可审计检查点暂停）、`windowsByProvider`（可选按 provider 配置 `{ maxRequests, windowMs? }`；无上游确认数据时本地统计显式标为 `local-estimate`） |
| `circuitBreaker.*` | 异常调查与熔断阈值（严格字段白名单）：`enabled`（默认 `true`）、`investigatorRole`（`arbiter`/`discussA`/`discussB`/`gate`，默认 `arbiter`）、`zeroProgressTruncationSoft`/`Hard`（默认 `5`/`10`）、`repeatedFailureSoft`/`Hard`（默认 `8`/`15`）、`identicalSignatureSoft`/`Hard`（默认 `5`/`9`）、`stagnantSpinSoft`/`Hard`（默认 `40`/`75`）、`runtimeErrorSoft`/`Hard`（默认 `3`/`6`）、`cooldownMs`（默认 `30000`）、`maxConsolidationsPerAgent`（默认 `2`） |
| `gate.sandboxDirectAllow` / `enablePatternCache` | 分层安全门开关（默认均为 `true`）：工作区沙箱内合规读写与常规构建直接确定性放行（`by="sandbox"`），跨边界同类安全命令命中模式缓存免重复调模型 |
| `team.executionPool` | 领队可为成员选择的模型列表（随附配置中的 `codex/`、`zcode/` 等为示例路由，需按本机网关与模型改写） |
| `team.autoIncludeUpstreamModels` | 默认 `false`。上游发现只展示候选，选择后才入池；显式启用自动入池仍尊重 disabledModels/disabledFamilies。 |
| `team.disabledModels` / `disabledFamilies` | 从成员候选池（含自动发现的上游模型）中显式禁用的模型路由列表或模型家族列表 |
| `team.maxMembersPerTeam` / `maxActiveMembers` | 每个用户任务最多派发的执行成员总数（随附配置默认 `128`）与初始用户最大并发上限（随附配置默认 `6`；未填时回退 `min(maxMembersPerTeam, 8)`）；运行中可通过 `scripts/dev/set-max-members.mjs`（写全局 `<storage>/concurrency.json`）、`leaderteam.local.json` 或当前会话用户消息行首 `最大并发 <N>`（写会话级 `teams/<id>/concurrency.json`）实时调整而无需重启 |
| `scheduler.*` | 资源感知弹性并发调度器参数（可选）：采样与控制轮询周期（`sampleIntervalMs`/`pollControlMs`）、分波渐进扩容步长与观察窗（`rampStepSize`/`rampObserveMs`）、滞回防抖阈值与冷却（`highCpuPct`/`recoverCpuPct`、`lowFreePhysMib`/`recoverFreePhysMib`、`lowFreeCommitMib`/`recoverFreeCommitMib`、`hysteresisCooldownMs`/`hysteresisRecoverSamples`）、按档位内存估算（`memberMemoryMib`）、以及并发 shell / 安全门积压 / 429 限流窗口阈值 |
| `timer.*` | 工程计时器配置（可选）：`enabled`（默认 `true`）、`elevatedAfterMs`（时间压力升高阈值，默认 10 分钟）、`stagnationAfterMs`（规划停滞告警与择优解锁阈值，默认 25 分钟）、`idleGapCapMs`（跨会话空闲折算上限，默认 5 分钟） |
| `planArchive.*` | 外部历史计划库配置（可选）：`enabled`（默认 `true`）、`root`（固定外部绝对路径，`null` 默认 `<storage>/plan-archive`；任何位于项目工作区或本仓库内的路径均以 `PLAN_ARCHIVE_INSIDE_PROJECT` 硬拒绝）、`minUnapprovedPlansForFallback`（触发防停滞择优的最少被打回计划数，默认 2）、`allowAutoFallbackOnDispatch`、`useArbiterForBestPlan`（默认 `true`） |
| `plugins.*` | 模块化子插件软开关（可选）：`scheduler`、`consensus`、`timerArchive`、`panel`（默认均为 `true`，也可直接在 Cordis patch 中对单个子插件设 `disabled: true` 物理拆卸） |
| `team.maxPlanAgreements` / `maxDiscussionsPerTask` | 连续未批准计划的兜底上限（默认 4）与可选单任务讨论上限（默认 null）。批准后重新计数；同一修订链必改项严格递减时允许继续解决，不以增加固定上限掩盖停滞。 |
| `profiles.leader` | 领队预设 id 与工具清单 |
| `profiles.<id>` | 成员工具档位：`preset`（DSH 预设 id）、`tools`、`mutating`、`description` |
| `toolPolicy.additionalTools` | 部署允许额外按任务授权的工具名称；仍须在目标预设实际注册，未知工具默认不可用 |
| `skills.roots` | 额外技能发现目录，必须位于工作区或配置参考目录；发现只回元数据，不自动加载正文 |
| `gate.scope` | 固定为 `team`：只管 LeaderTeam 会话，普通会话保持原样。`all` 不受支持，配置为 `all` 时拒绝启动 |
| `gate.uncontrolledTools` | 不需模型审查的只读/协调工具；禁止将 `team_dispatch`、`team_note`、`write`、`edit`、`bash`、`pwsh` 或任何 `mutatingTools`/`shellTools` 配入此列表 |
| `gate.mutatingTools` | 受“先读必读参考”约束的工具 |
| `gate.pathArgs` | 需做路径检查的工具参数 |
| `gate.dedupeDeniedCalls` | 默认 `true`：同一成员重复提交相同工具与参数哈希且已被模型拒绝时，直接拦截不再重复调模型 |
| `gate.maxReviewsPerMember` / `maxReviewsPerTask` | 单成员、单任务的模型审查次数兜底上限（随附配置 400 / 2000；`null` = 不限）。两次真实运行的峰值是单成员 111、单任务 172，兜底只用来挡失控循环 |
| `gate.maxDenialsPerMember` | 同一成员**连续**被拒达到该数（默认 10）即熔断。审查故障（`gate-error`）和"先读引用"的提醒（`rule:refs-unread`）不计入 |
| `gate.maxConsecutiveGateErrors` / `gateErrorCooldownMs` | 同一调用者连续遇到该数量（默认 5）的审查故障后，在冷却时间（默认 60000 毫秒）内不再调用模型，直接以 `rule:gate-unavailable-circuit-breaker` 拒绝；冷却过后放行一次试探 |
| `gate.ruleOnlyTools` | 只走确定性规则、不调用模型的工具（随附配置 `["team_note", "team_plan", "team_conference"]`；校验白名单仅允许这三个内部治理/参考工具，其他工具填入会被配置校验拒绝）。放行同样写入 `gate.jsonl`（来源 `rule-only`） |
| `roles.<角色>.fallback` | 治理角色（gate、discussA、discussB、arbiter）的备用路由，按顺序排列，最多 4 条，每条 `{route, effort}`，可另带 `maxTokens`、`timeoutMs`、`retries`。只有前面的路由**不可用**（超时、上游错误、额度耗尽、输出无法解析）时才用下一条；模型给出的任何结论（包括拒绝）都是终局，不会换路由重问 |
| `team.leaderModelAsLastResort` | 默认 `true`：每条治理角色路由链的最后一环是领队当前所用的模型（必须是 `models` 里已有的路由），以一次独立的新请求调用。非首选路由完成的结果在回执和用量账本里标记 `degraded: true` 与 `via`（`fallback` 或 `leader`），`team_discuss` 结果里列出 `degraded_roles` |
| `quota.*` | `stateFile`（可为 `null`）、过期秒数、耗尽/偏低阈值、`allowUnknown`（非 GPT 默认 `true`）、`allowUnknownGpt`（GPT 默认 `false`）、`gptReservePct`（GPT 保留百分比，默认 `3`） |
| `paths.globalRefRoots` | 全局参考根（领队与成员只读可访问，任何工具不可写） |
| `paths.projectRefsDir` | 项目参考目录（仅 `team_note` 可写） |
| `paths.protectedDirs` | 文件工具不可写的工作区路径（目录或单个文件）。默认 `.leaderteam`、`.git`、`.agents`、`AGENTS.md` |
| `paths.leaderReadRoots` | 领队额外可读的只读目录（绝对路径，可选，默认空）。只对领队生效，成员不继承。不在工作区、全局参考根和这份清单内的路径，领队必须先请示用户 |
| `team.requirePlanAgreement` / `planExemptProfiles` | 派发写入型成员前必须有通过的 plan 讨论；只读侦察豁免 |
| `agreement.*` | 轮数（默认 3）、提案与证据上限、裁断尝试次数 |
| `storage.root` | 团队数据根，`null` = `$DSH_HOME/leaderteam` |

## 2. 领队工具

| 工具 | 输入 | 行为 |
|---|---|---|
| `team_models` | 无 | 执行池每个模型的能力说明、档位、额度状态（ok/low/exhausted/unknown）、剩余百分比、重置时间、近期每档位 p50 token；安全门/讨论/裁断路由的额度；`leader_model`（配置的领队、本会话实际模型、核对结果）与实时弹性并发摘要 `concurrency` |
| `team_concurrency` | pending_parallel_tasks?, leader_max_parallel? | 查询实时执行子代理并发数、本机 CPU/物理内存/Windows 提交空间余量、模型限流与安全门队列瓶颈及滞回状态；领队可结合任务轻重主动设置 `leader_max_parallel`（`0` 恢复自动）或登记待派发的独立并行任务数 `pending_parallel_tasks`（容量恢复或用户调高上限时自动唤醒补派）；固定治理角色不计入 |
| `team_plan` | action(overview/stage/verify/state), ... | 增量维护外部滚动规划账本：记录任务全局概览（`overview`）、定义就绪或暂定阶段契约（`stage`）、登记阶段实测验收证据（`verify`）及查询前沿状态（`state`） |
| `team_dispatch` | name, stage_id? / task?, acceptance[]?, model, effort, profile?, tools[]?, defer_tools[]?, skills[]?, write_scope[]?, refs[]?, plan_id? | 在自治模式（`governance.mode="autonomous"`）下就绪阶段可直接派发而无需等待 `plan_id`（后台自动触发去重异步监督）；校验实时弹性并发上限、单任务成员上限、预设注册工具、必读资料、写范围与配额后启动成员 |
| `team_direct_exec` | task, write_scope[]?, allow_shell?, effort?, acceptance[]? | 领队高频直属执行模型：无需创建正式阶段即可执行局部探查、冒烟验证或定点修复；严格锁定在工作区沙箱内运行且每次工具操作均过安全门（正式裁断会商期间自动挂起） |
| `team_conference` | action(status/respond), conference_id?, explanation?, new_evidence_files[]?, proposed_alternative? | 查询当前正式裁断会商状态，或在会商中向独立裁断陈述工作区事实依据、补充证据文件及替代技术方案 |
| `team_tools` | action(list/load), profile?, names[]? | 领队按目标预设发现真实工具元数据与 available；成员只看本任务获授目录。load 只加载已获授工具，下一步骤生效，不扩大授权 |
| `team_skills` | action(list/read), id? | 发现时只回技能摘要（纯中文名称生成确定性哈希 id，与发现顺序无关）；派发选中技能正文注入目标成员系统指令；成员只能读取获授快照 |
| `team_discuss` | kind(plan/delivery/dispute), topic, proposal, evidence?, evidence_files[]?, revises?, resume_id? | 运行对称讨论；双方与裁断者都收到用户原始请求、`project_timer` 工程耗时压力及请求中点名的中英文或引号含空格文档（`auto_evidence_files`）；证据超限时显式标记 `evidence_truncated`；所有计划自动分类归档至外部计划库；`revises`=上次同类讨论 id 时携带上次必改项并将原计划标为已取代 |
| `team_plan_archive` | action(timer/list/get/select_best/retrospect), plan_id?, category?, lifecycle_state?, project_only?, limit?, notes? | 查询项目与当前任务工程计时器（`timer`）、按 10 类主题或生命周期检索外部历史计划（`list`/`get`）、在多轮打回停滞时从非一致 `reject` 候选中由裁断者/评分择优放行最佳方案（`select_best`）、或在执行后对照成员产出与安全门记录生成问题复审报告（`retrospect`） |
| `team_note` | path（相对 `.leaderteam/refs/`）, content, mode | 校验词法与真实路径均位于 `.leaderteam/refs/` 内后，原子写入或追加项目参考 |
| `team_status` | 无 | `leader_model`、当前 `task_seq`、插件挂载状态 `plugins`、工程计时器 `timer`、外部历史计划统计 `plan_archive`、完整实时弹性并发快照 `concurrency`、成员列表及实时生命周期状态（`starting`/`started`/`running`/`done`/`blocked`/`cancelled`/`failed`）、讨论记录、安全门统计与最近拒绝 |

领队专用工具先核对其配置模型与档位。工具投影同时过滤继承工具和预设自身注册；成员只获得本任务 tools 中已加载的描述，两个能力控制工具保持可用。普通会话保持原有工具。完整目录、延迟加载、技能与配置 CLI 见《07-按需工具与技能》。

文件读写工具受词法与真实路径双重边界：成员读取只在工作区和配置参考根；领队另可读 `paths.leaderReadRoots`，其余路径需要用户在本会话里发一条以 `允许读取 ` 或 `allow read ` 开头、后跟绝对路径的消息行才可读（授权该文件或该目录之下，只读，只对领队，整盘根目录无效，只认用户本人输入的消息）；write/edit 限定 write_scope，必读参考未完成时拒绝受控操作。shell 仍依赖独立审查、官方工作区写沙箱和系统权限，没有成员子目录或工作区外读取的系统硬隔离。成员不可使用领队专用工具。

## 3. 安全门决策顺序（每次工具调用，工具主体执行前）

1. 调用者不属于任何 LeaderTeam 团队 → 原样放行。
2. 工具对该调用者不可见 → 交给 DSH 返回 UNKNOWN_TOOL，不审查。
3. 硬规则（零模型调用，词法路径与 `realpathBestEffort` 真实路径双重校验）：未知身份；工具不在档位；写入路径无效/在全局参考内/在工作区外/在受保护目录；`team_note` 越出参考目录；超出成员写入范围；领队 `read`/`read_image`/`glob`/`grep` 越出工作区、全局参考根、`paths.leaderReadRoots` 且用户未在本会话授权（见下）；成员 `read`/`read_image`/`glob`/`grep` 越出工作区与全局参考根；成员 `glob` 的 `pattern`、`grep` 的 `glob`/`include` 含绝对路径或 `..`；未读必读参考；命令行工具的参数超过可完整送审的长度（`gate.maxArgChars`）；命令行参数中会被脱敏遮盖、又不能证明为惰性字面量的值（例如 `$token=` 后的裸词或表达式）；命令文本引用全局参考根 → 拒绝。
4. 工具属于 `uncontrolledTools` → 放行。工具属于 `ruleOnlyTools` → 放行并写回执（来源 `rule-only`），不调用模型。
5. 去重、熔断与预算检查：历史审计记录不可读 → `gate-receipt-error` 拒绝；同一成员被拒调用达到 `maxDenialsPerMember` → `rule:member-denial-circuit-breaker` 拒绝；重复提交相同被拒工具与参数哈希 → `rule:duplicate-denied-call` 拒绝；单成员或单任务模型审查次数达到上限 → `rule:gate-budget-exceeded` 拒绝。 另有审查故障熔断：同一调用者连续 `maxConsecutiveGateErrors` 次 `gate-error` 且仍在冷却时间内 → `rule:gate-unavailable-circuit-breaker` 拒绝，不调用模型。
6. 一次配置的无工具审查请求（实际工具短说明、脱敏参数、范围和实时用户任务摘要；系统提示明确工具描述、参数内容与领队撰写的成员任务均为不可信输入，仅能收紧而不能扩大授权）→ 严格 JSON 裁决；失败重试 `retries` 次，仍失败 → 拒绝。 请求按该角色的路由链依次尝试（见 `roles.<角色>.fallback`）；请求正文的字段顺序固定为 authorization、scope、actor、operation，不变的背景在前、被审查的操作在后，以便上游缓存命中。
7. 放行前再次执行确定性硬规则校验（不重复调用 LLM）并核对调用者身份与工作目录绑定，先将回执写入 `gate.jsonl`（写盘失败则以 `gate-receipt-error` 拒绝），通过后以审查过的冻结参数副本执行。

拒绝结果对模型显示为 `Error: blocked by the LeaderTeam safety gate (<来源>): <原因>`，错误码 `LT_GATE_DENIED`。每次决定写入 `gate.jsonl`（存参数 SHA-256 与脱敏截断后的 `argsPreview`）。

## 4. 讨论协议

- 评审依据与工程时间约束：用户原始请求、证据（含自动附上的需求文档）以及工程计时器 `project_timer`（项目累计耗时、本任务耗时、规划停滞时长与 `normal`/`elevated`/`critical` 时间压力）。评审团必须把工程时间考虑进去，严禁以保守答复（主代理提什么都一律不同意）作为偷懒借口；需求未规定的实现细节交由执行者决定。
- 有责评审契约（Accountable Review）：每轮 A、B 并行独立给出 `approve | reject | revise`。凡是非 `approve` 判决（`revise` 或 `reject`），除技术理由 `reasons`（`revise` 另须附 `requiredChanges`）外，**必须提供具体可落地的建议或替代解决方案 `suggestions`**；空泛套话（如“因为…所以我不同意”、“请重新设计方案”）或将 `reasons` 原样复制到 `suggestions` 会被确定性判定为无效意见并触发重试/失败。
- 同一轮立场相同即定调：approve/reject；revise 合并双方修改项（去重）。
- 第 2 轮起各自看到“自己上一轮意见”和“对方上一轮意见”，表述完全对称。
- 第 3 轮仍不同 → 裁断者一次性输出 `{"adopt":"A"}` 或 `{"adopt":"B"}`，结果取被采纳方最后一轮意见。
- 事件逐条落盘（created / opinion / arbiter-attempt / ruling），重放即可恢复；裁断最多一次。

## 5. 数据文件

`<storage>/plan-archive/`（或显式外部路径 `planArchive.root`）：固定位于项目工作区与本仓库之外的历史计划库，内含全局索引 `index.json` 与按项目键分桶的计划记录、评审意见、执行成员结果及执行后复审记录（`retrospectives`），可通过 DSH 内嵌面板或 `scripts/plan-archive.mjs --clean` 集中清理，绝不污染业务项目目录。

`<storage>/concurrency.json`：可选环境级实时并发控制文件（由 `scripts/dev/set-max-members.mjs` 原子写入，运行中 500ms 内对整个存储根生效）；用户在单个领队会话行首输入 `最大并发 <N>` 时仅原子写入该会话私有的 `<storage>/teams/<领队会话 id>/concurrency.json`（不污染其他会话，纯并发控制指令不递增 `task_seq`、不使当前 `plan_id` 失效，同时多会话活跃成员共享全局池与设备动态容量余量）。

`<storage>/teams/<领队会话 id>/`：`team.json`、`timer.json`（跨会话工程计时状态）、`members.jsonl`（成员记录 + 生命周期状态转换事件）、`agreements.jsonl`、`agreements/<id>.input.json`（讨论输入，续跑用）、`gate.jsonl`（回执与脱敏参数摘要）、`usage.jsonl`（LeaderTeam 自己发出的每次无工具模型请求：`role` gate/discussA/discussB/arbiter、`route`、`effort`、`ok`、`attempts`、门的 `tool`/`callId`/`member` 或讨论的 `agreementId`/`kind`，以及宿主报告的 `usage`：inputTokens/outputTokens/totalTokens/reasoningTokens/cacheReadTokens/cacheWriteTokens，重试各次合计；成员与领队自身的用量在 DSH 会话日志里，不在此文件）。追加写前若末尾存在上次崩溃留下的不完整残行，会自动原地截去残行后再追加完整记录；中间行损坏仍视为数据损坏并报错（`STORE_CORRUPT`）。

## 6. DSH 内嵌控制台、模块化插件与模型配置器

LeaderTeam 按 DSH Cordis 插件规范拆分为六个独立子插件（位于 `leaderteam/plugins/`）：
- `leaderteam-core`：基础运行时与最终调度安全门（核心底座）。
- `leaderteam-lead`：领队工具集、成员派发与按需工具/技能投影。
- `leaderteam-scheduler`：资源感知弹性并发调度器（拆卸后回退至静态 `maxActiveMembers`）。
- `leaderteam-consensus`：对称双评审与裁断（拆卸后 `team_dispatch` 免除 `plan_id` 门禁，直接派发并受安全门保护）。
- `leaderteam-timer-archive`：工程计时器与固定外部历史计划库（拆卸后隐藏 `team_plan_archive`）。
- `leaderteam-panel`：直接挂载在 DSH Desktop/Web 左侧栏与右侧标签页内的 **LeaderTeam 控制台**（拆卸后仅移除 UI 面板与 `/api/leaderteam-panel/*` 接口）。

- **DSH 内嵌可视化控制台（`leaderteam-panel`）**：在 DSH 窗口内直接点击侧栏 LeaderTeam 图标打开，支持一键探测 DSH 上游当前接入的所有 provider 与模型（含非预置 provider 与 `effort: "none"` 模型），可视化切换 `leader`/`gate`/`discussA`/`discussB`/`arbiter` 五角色模型与档位、勾选成员执行候选池、查看项目工程计时器、检索外部历史计划库、对任意历史计划发起执行后复审或按条件一键清理，成员池、档位与计时阈值可即时更新；治理角色、安全规则和插件策略按团队冻结，修改仅对新会话生效。
- **命令行（`scripts/configure-models.mjs`）**：
  - 查看当前配置与 Desktop 同步状态：`node scripts/configure-models.mjs --status`
  - 成员候选池管理：`--pool-set <r1,r2>`、`--pool-enable <r>`、`--pool-disable <r>`、`--pool-enable-family <f>`、`--pool-disable-family <f>`（例如 `--pool-disable-family gpt` 一键从成员池排除 GPT 模型）
  - 新增或修改模型及可选档位：`--upsert-model <provider/model> [--family ...] [--label ...] [--efforts low,medium,high] [--default-effort medium] [--strengths ...] [--quota-windows ...] [--enable-in-pool]`；移除未使用模型：`--remove-model <route> [--prune-pool]`
  - 治理角色与领队核对策略：`--set-role <role>=<provider/model>[:<effort>]`、`--leader-policy <enforce|warn|off>`
  - 写入目标与校验：默认原子写入 `config/leaderteam.config.json` 并自动同步 `config/desktop-magpie.patch.yml` 与 `config/magpie-models.patch.yml`；加 `--local` 则只写本机覆盖 `config/leaderteam.local.json`（修改前同时校验单文件与合并后配置，杜绝半成品落盘）；加 `--dry-run` 仅预览零写盘。
- **本机回环可视化面板（`scripts/open-model-config.ps1` 或 `--serve --open`）**：仅监听 `127.0.0.1` 随机端口并启用 `Host`/`Origin` 校验与一次性 `X-LT-Token` 防护，可在浏览器中勾选成员候选模型、勾选允许推理档位、新增模型、切换治理角色并预览保存。
- **运行中实时热重载与 Desktop 同步边界**：
  - 通过 DSH 内嵌 `leaderteam-panel` 探测到的上游模型与已注册模型：开关成员候选池、调整执行档位/特长说明立即对后续派发生效；治理角色与 `leaderModelPolicy` 仅在新建团队时生效。
  - 若通过外部 CLI 离线新增了此前未在 Desktop `cordis.patch.yml` 注册的模型路由，可在退出 DSH Desktop 后执行一次 `node scripts/configure-models.mjs --sync-desktop` 同步静态 patch。
