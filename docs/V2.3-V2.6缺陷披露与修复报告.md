# LeaderTeam V2.3–V2.6 缺陷披露与稳定性修复报告

- **发布版本**：`windows-v2.6.0`（V2.6 长期维护稳定线首版）
- **覆盖时间线**：`v2.3.0` → `v2.3.1`（Issues #1–#4）→ `v2.4.0` → `v2.5.0` → `v2.5.1` → **`v2.6.0`**
- **编制原则**：不包装新概念、不回避历史问题。本报告如实汇总自 `v2.3.0` 发布以来在跨平台适配、宿主集成、长程执行、模型路由、衡账计量与前端交互中暴露的全部主要真实缺陷、根因定位、修复措施、验证结论，以及目前**仍未彻底关闭的开放问题与验证边界**。

---

## 一、版本定位说明

- **V2.6 是面向稳定性的长期维护基线**：核心目标是收敛 `v2.3` 至 `v2.5.1` 在真实工程与跨平台运行中暴露出的高影响缺陷，后续将按实际使用与外部反馈推出 `v2.6.1`、`v2.6.2` 等维护版，不再以高频概念迭代替代稳定性修复。
- **不引入 V2.7 新架构**：原计划中的 Context Core 留给 `v2.7`，本版不引入其代码；Rust 原生映射核心源码（`rust/mapper/src`）在 `v2.3.0` 至 `v2.6.0` 之间保持零改动（Tree Hash `7e850719d2336177ddd249055d8736d7b8173595`）。
- **双平台独立发版说明**：Windows 与 Linux 共享通用修复与设计契约，但各自独立完成宿主验收与发版，互不阻塞。本报告中的实测数据明确区分 Windows 完整宿主验收与 Linux 已完成验证范围。

### 2.2 V2.4.0 – V2.5.1（产品化、双模、Windows 全栈适配与前端修正）

#### A. 网关、模型池、双模与跨协议缺陷
1. **删除网关供应商后 DSH 宿主残留孤立 `ltgw-*` 路由**：删除供应商未同步清理 DSH `settings`，导致下拉菜单保留失效路由。已通过 DSH `settings.mutate` 同步注销并过滤孤立路由（`v2.5.0`+）。
2. **「✨ 一键自动配齐角色」（`autoAdoptHost`）产生重复 `executionPool` 路由导致保存失败**：多源目录（宿主目录 + 网关目录）同时返回同一路由时未按 `route` 去重。已按 `route` 幂等去重并优先选取已接入的 `ltgw-*` 模型（`v2.4.0`–`v2.5.1` Windows 版）。
3. **跨协议流式错误落账与 `probe_failed` 时序丢失**：上游 SSE 流内报错后未在关闭响应前完成账本与探测状态落盘。已改为先落账再结束响应（`v2.4.0` r2 / `v2.5.0`+）。
4. **同工作目录新建会话被误复用覆写预设 & 纯 Single 幽灵目录**：新建会话时同目录旧会话被 `reuseLive` 覆盖预设，且纯 Single 会话产生多余 `teams/` 目录。已显式拒绝 `SESSION_ALREADY_EXISTS`、实现纯 Single 零 `teams/` 磁盘开销，并在 `inFlightPromptSessions` 期间锁定模式切换（`v2.5.0`+）。
5. **V2.4 `/api/lt-v24/sessions` 新建会话未绑定 `leaderteam` 预设**：导致纯 Team 模式下直接通过工作台创建的会话未激活领队工具面。已补齐默认 `agentPreset: 'leaderteam'`（`windows-v2.4.0`）。

#### B. Windows 平台深度适配与安全门加固（真实桌面环境暴露）
1. **Windows `pwsh` 安全门词法绕过**：此前对 `pwsh` 复用 POSIX 词法扫描器，将反斜杠 `\` 误当转义符剥离（例如 `..\outside.txt` 被误判为工作区内路径），未解码 PowerShell 反引号混淆（``Remove`-Item``），且跳过了 `win32` 下 `workdir`/`cwd` 硬规则与工作区内 NTFS 目录联接（Junction）越界检查。已新增独立 `'pwsh'` 词法方言、补齐 `workdir` 与 NTFS Junction `realpath` 双向校验，并封堵对 `vault.json`、`.credentials.yaml`、`.env`、`providers.json`、`session-modes.json` 的越权读写（`windows-v2.4.0`+）。
2. **NTFS 目录联接（Junction）导致双网关冲突与衡账双计**：当 `%USERPROFILE%\.dsh` 为指向数据盘的 NTFS Junction 时，字面路径与真实路径哈希不一致导致重复拉起网关、衡账误判 `FORBIDDEN_HOME` 或重复计量。已统一经 `realpathSync.native` + Windows 大小写归一化处理，并补齐衡账 `sessionId` 对 NTFS ADS（`:`）和保留设备名的拦截（`windows-v2.4.0`+）。
3. **Windows `MoveFileExW` 句柄竞争与锁误删**：并发读或安全软件扫描瞬间 `fs.renameSync` 抛 `EPERM`/`EACCES`/`EBUSY`，锁文件竞争误判导致写盘失败。已加入有界退避重试与持锁令牌校验（`windows-v2.4.0`+）。
4. **悬空 `%LOCALAPPDATA%\pnpm\store` Junction 导致安装/升级报 `[ENOTDIR]`**：Windows 用户迁移缓存盘后残留悬空联接导致 `dsh plugin add` 直接失败；且安装器与更新器曾使用不同回退路径引发 `ERR_PNPM_UNEXPECTED_STORE`。已统一探测悬空联接并回退至 `<DSH_HOME>/leaderteam/pnpm-home`；同时前置识别未首次启动的 `desktop` Profile 给出明确中文提示（`windows-v2.4.0`+）。
5. **应用内一键升级/回滚的三大 Windows 阻塞**：
   - **假忙锁死**：运行过任意 Team 会话后 `liveProcessMemberIds` 未清理，导致 `isRuntimeIdleForUpgrade` 永久拒绝升级；已改为核验成员真实运行态；
   - **V8 ESM 传递缓存与中文路径乱码**：进程内热替换无法刷新传递子模块且 `cmd.exe` 在中文路径（CP936）下乱码；已改为优先无壳直调官方桌面端 Electron CLI（`shell: false` + `ELECTRON_RUN_AS_NODE=1`）并诚实提示重启生效；
   - **原生 `.node` DLL 映像锁（`[ERR_PNPM_EPERM]`）**：Windows `LoadLibraryW` 锁定 `node_modules` 中的 `mapper.win32-x64.node` 导致在线覆盖安装失败；已改为基于内容 SHA-256 的 `%TEMP%/leaderteam-native-cache/` 影子副本加载解除目录锁（`windows-v2.4.0`+）。
6. **Node 24 下截断 Zstd 帧校验**：兼容 Node 24 RFC 8878 截断帧精确识别与损坏尾帧挽救（`windows-v2.4.0`+）。
7. **V2.5.1 `/lt` 工作台两项核心显示回归**：
   - 用户消息在 `/lt` 渲染为 `(空消息)`（原因：仅读取 `ev.data.message`，忽略 DSH 直接挂载的 `ev.data.content`）；
   - 空闲态经「本会话配置」切换模型后，输入框底部模型胶囊未随本会话配置实时刷新。
   - 两项均已在 `windows-v2.5.1`（`fca94b5`）定点修复并通过真实浏览器复验。

## 四、诚实披露：当前仍开放的问题与验证边界（留待 V2.6.x 按需收敛）

1. **三项仍开放的深层架构收敛项（不影响主路径稳定运行，将在 `v2.6.x` 按实际影响逐步处理）**：
   - **`ARCH-03` 剩余两项**：① 宿主请求头注入钩子在缺少结构化归属上下文时，仍会回退扫描历史成员目录；② 模型配置仍分散维护在主配置、本地覆盖、网关库、DSH 设置等多处文件中。
   - **`ARCH-04` 剩余一项**：未随主包发行的旧版扩展（`dsh-context`）仍保留独立衡账逻辑（主插件与独立衡账包 `lt-usage-plugin` 已完全对齐）。
   - **`ARCH-05` 剩余一项**：DSH 内嵌侧栏面板（`client.js`）与独立 `/lt` 工作台仍并存三套重叠 HTTP 接口。
2. **Windows 网关首次启动偶发失败的持续观察**：
   - RC1 浏览器复验中曾观测到一次本地网关首次启动失败（同实例重试与全新配置独立复验均一次通过）。本版已将 Windows 网关子进程冷启动超时由 `8s` 放宽至 `15s` 以覆盖冷启动与安全软件扫描尖峰，但因偶发事件未能稳定复现，如外部用户在桌面端仍遇到首次启动失败，请导出 `lt-bugreport` 日志反馈以便在 `v2.6.1` 根治。
3. **Linux 侧当前未闭环范围（按双平台独立发版原则，不阻塞 Windows 发行）**：
   - 在深层中文路径下使用 `pnpm` 离线安装 `.tgz` 会触发 `ERR_PNPM_ENAMETOOLONG`（将安装包复制至短路径即可安装）；
   - 当前本地 WSL2 的 DSH Web 宿主环境缺少 `node-addon-require-builtin-linux-x64-gnu` 导致空白配置与装包配置启动均退出，因此 Linux 侧 Web 工作台、会话流转及升级回滚仍待完整 Linux 宿主环境独立验收后再发布 `linux-v2.6.0`。
