# 可视化与用量

从桌面“DeepSeek Harness - LeaderTeam”进入正式环境。会话中的“编队”显示领队与成员的关系；成员卡直接显示实际模型和推理档位，点击卡片可看成员详情。没有实际记录的值显示未知，不用派发声明或默认配置冒充实际调用。

左侧“上下文洞察”中的“模型累计实报用量”汇总当前 `DSH_HOME` 环境下的**全部会话**（含普通非团队会话，领队与成员会话合并显示在会话行，会话行不区分推理档位）以及 LeaderTeam 辅助角色账本（`leaderteam/teams/*/usage.jsonl`；若配置了自定义 `storage.root` 或未通过启动器注入 `DSH_HOME` 环境变量，则扩展无法定位辅助账本）。它提供按模型、来源和角色筛选，尚不按单个团队或单次任务切分。默认每 30 秒更新，也可点击“刷新”。

会话量取每个会话自己的累计计量，包含领队和子代理，每个会话只加一次；不再次叠加父会话的子代汇总。安全门、讨论 A/B 和裁断从当前 Harness home 的 `leaderteam/teams/*/usage.jsonl` 取量，每个物理账本行只加一次，重试用行内实报合计，不再乘尝试次数。

“非缓存输入”与缓存读取、缓存写入分别展示。会话总计为这三项加输出；辅助角色使用上游实报总计。推理包含在输出中，不额外加到总计。缺失的计量保持未知，统计只合计已报告部分；未载入或未报告计量的会话有单独计数。历史会话的累计模型分桶没有推理档位时，表中显示“档位未知”；成员卡仍显示其最后实际调用的档位。

本页不合并 Magpie 的跨应用全局用量，不把 token、上下文占用百分比、套餐剩余额度混成一个数字。

## 安装与恢复

使用固定上游 dsh-context 0.82.1（提交 `cc481fc070dff5fec57e9d8381f70698f546f59e`）的小范围扩展，安装包版本为 `0.82.1-leaderteam.1`。源码在 `extensions/dsh-context/`，安装包在 `packages/dsh-context/`；没有修改官方 `app.asar`。入口将两个宿主 peer 绑定到正在运行的官方 Desktop；余额查询端点没有启用。

安装前完全退出正式 Desktop。使用当前官方捆绑 CLI，并只对子进程设置 `DSH_HOME`：

```powershell
$paths = Get-Content -LiteralPath '.\config\official-desktop.paths.json' -Raw -Encoding UTF8 | ConvertFrom-Json
$env:DSH_HOME = $paths.home
& (Join-Path $paths.app 'resources\runtime\cli\bin\dsh.cmd') plugin --profile desktop add (Resolve-Path '.\packages\dsh-context\dsh-context-0.82.1-leaderteam.1.tgz').Path
```

安装后从桌面入口重开。如需停用，先完全退出，再用同一 CLI 执行 `plugin --profile desktop remove dsh-context`；LeaderTeam 核心独立保留。

## 后续构建

在 `extensions/dsh-context` 中使用符合包声明（`^22.19.0 || >= 24.0.0`，建议 Node 24）的 Node.js 与 pnpm，运行 `pnpm install --frozen-lockfile --ignore-scripts`、`pnpm run build`。运行 `node prepare-release.mjs` 得到新的打包目录，在该目录执行 `pnpm --config.ignore-scripts=true pack --pack-destination <输出目录>`。保留宿主入口和包清单，不直接将原始上游的 `lib/index.js` 作为官方 Desktop 的外置入口。

新构建先进入无凭据隔离环境，按当前全部核心场景验收，再验证实际成员、用量对账与重启；正式安装前备份配置。
