# LeaderTeam V2.1 使用指南

本文介绍 LeaderTeam V2.1 在官方 DeepSeek Harness Desktop（`0.2.2-rc.1`）中的日常工作流、模型与角色配置、异步治理机制及常见问题处理。首次安装步骤见《[官方Desktop部署与恢复](官方Desktop部署与恢复.md)》。

---

## 一、快速开始与日常工作流

1. **启动环境**：通过桌面快捷方式 **DeepSeek Harness - LeaderTeam** 或运行 `.\scripts\start-official-desktop.ps1` 打开窗口。
2. **新建团队会话**：
   - 选择需要处理的项目工作区文件夹；
   - 在会话预设中选择 **LeaderTeam**，并确认当前会话模型与配置的 `roles.leader` 一致；
   - 直接用自然语言发送工程需求（无需手工拆分阶段或指定子代理模型）。
3. **自主施工与并行监督**：
   - 领队会先用 `team_plan(action="overview")` 建立紧凑的全局概览，随后增量定义就绪阶段（`stage`）并**立即通过 `team_dispatch` 并行派发执行成员**，或通过 `team_direct_exec` 执行局部探查、冒烟测试与小修补。
   - 双评审（`discussA` / `discussB`）在后台异步监督阶段契约与工程实现：常规建议以无阻塞方式回注领队，领队可通过 `send_message` 或参考笔记实时补充给成员。
   - 单轮输出若达到模型单次 `max-tokens` 上限，系统会自动保留上下文与已成功工具记录无缝续接，无需人工干预。

## 二、内嵌控制台与模型配置

你可以随时通过 **DSH 窗口左侧栏的 LeaderTeam 图标**打开内嵌控制台（或使用 CLI `scripts/configure-models.mjs`）：

- **一键探测上游模型**：自动读取上游网关 `/v1/models` 暴露的真实模型列表、上下文窗口（`contextWindow`）与最大输出（`maxTokens`）。
- **角色与执行池配置**：
  - 独立设置 `leader`（领队）、`gate`（安全门）、`discussA` / `discussB`（双评审）、`arbiter`（独立裁断）、`directExec`（直属执行）的模型路由、推理档位与 `fallback` 备用降级链。
  - 自由勾选普通成员候选执行池（`team.executionPool`）。
  - **热生效边界**：成员候选池、档位说明与并发上限修改后对后续派发立即生效；固定治理角色与安全策略按团队会话冻结，修改后对新建会话生效。
- **实时调整最大并发数**：
  - 在任意团队会话中单独发送一行 `最大并发 4`（仅对当前会话立即生效，不打断在途任务、不开启新任务序号）；
  - 或运行 `node scripts/dev/set-max-members.mjs --max 6` 调整全局默认上限。

## 三、争议裁断与人工介入说明

正常工程推进中不会暂停流水线。仅当发生以下两类情况时，治理或人工程序会介入：

1. **正式二方裁断会商（自动自治处理）**：
   - 当双评审对同一阶段/派发一致提出强制干预异议，且「双评审 + 独立裁断」三方预议达到 2/3 多数时，系统会先通知所有在途成员写下即时交接检查点并有序暂停，随后开启「独立裁断 ↔ 领队」正式会商。
   - 会商结束后按裁断结论自动恢复无争议成员或落实必改要求（整改须经实质验证后才允许宣告交付）。
2. **需要人工介入的场景（`waiting_user` / `blocked`）**：
   - **第三次同案一致异议上调人工**：同一底层事件与实际行为若连续第三次触发双评审一致异议，不再重复开会，系统会整理完整争议摘要与可选方案交由你在聊天框直接拍板（回复你的决定后即自动解除挂起继续施工）。
   - **外部只读路径授权**：领队如需读取工作区与配置参考根之外的目录，会停下提示你发送一行：
     ```text
     允许读取 D:\你的外部参考目录
     ```
     该授权仅在本会话对领队只读生效。
   - **新目录 Windows 沙箱权限缺失（`Win32 5`）**：若共享盘或特定目录缺少当前用户的完全控制权限导致 `pwsh` 沙箱无法初始化，团队会先完成所有不依赖命令行的代码与文档工作，最后干净停机汇报，不会跨目录盲目绕行空耗额度。按《[官方Desktop部署与恢复](官方Desktop部署与恢复.md)》运行一次 `tools/dsh-sandbox-acl` 即可修复。

## 四、外部历史计划库与工程复盘

所有团队计划、阶段快照与复盘记录均存储在项目工作区之外的 `<DSH_HOME>/leaderteam/plan-archive/`（绝不污染业务代码仓库）：

```powershell
# 查看归档统计
node scripts/plan-archive.mjs --status

# 列出历史计划并对指定计划生成执行复盘
node scripts/plan-archive.mjs --list
node scripts/plan-archive.mjs --retrospect <planId>

# 安全清理 30 天前的历史归档（先 --dry-run 预览，确认后 --confirm 执行）
node scripts/plan-archive.mjs --clean --older-than-days 30 --dry-run
node scripts/plan-archive.mjs --clean --older-than-days 30 --confirm
```
